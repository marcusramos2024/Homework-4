     Plan: generateRoundRobin (US-3, first slice)

     Context

     US-3 needs a fair single round robin. This slice is only the pairing core:
     who plays whom in which round. Slots, venues, blackouts, back-to-back and
     late-slot rules come later and build on it. Pure TDD, five cycles.

     - src/lib/scheduler/ does not exist yet. src/lib/league/ does (types, Zod
       schema, validateLeague, tests) and gives the conventions to copy.
     - Reuse Result, ok(), err() from src/lib/result.ts. Errors there are typed
       codes (LeagueError), so the scheduler error should be a typed code too,
       not a string.
     - Tests sit next to the code: roundRobin.test.ts, and
       roundRobin.property.test.ts for the property test. Vitest already
       collects both (src/**/*.test.ts).
     - fast-check is already in devDependencies, so no dependency to ask about.
     - src/lib is pure: no Math.random, no Date. The seed has to drive a small
       seeded PRNG written in the module.
     - validateLeague already rejects duplicate team IDs league-wide, so the
       generator can assume IDs are unique. It still gets a cheap guard (see
       open items).

     PRD wording on byes is wrong

     US-3 says: "With an odd number of teams, each team gets exactly one bye per
     round."

     Read literally that is impossible: it says every team sits out every round.
     What is meant, and what your cycle 2 says, is two separate facts:

     1. Each round has exactly one bye (one team sits out).
     2. Over the season each team has exactly one bye (n teams, n rounds, n
        byes).

     Fix in docs/PRD.md: "With an odd number of teams, each round has exactly
     one bye, and each team gets exactly one bye over the season." Do this as a
     separate docs: commit before the red test, and tell the user the
     requirement text changed.

     Design

     File: src/lib/scheduler/roundRobin.ts (types exported from the same file,
     or types.ts if it grows).

     type Round = { games: [string, string][]; bye: string | null };
     type RoundRobinSchedule = Round[];
     type RoundRobinError = { code: "TOO_FEW_TEAMS"; count: number };
     generateRoundRobin(teamIds: string[], seed: number):
     Result<RoundRobinSchedule, RoundRobinError>

     Algorithm: circle method. Pad odd counts with a null placeholder; whoever
     pairs with it has the bye. Rounds = n-1 (even) or n (odd). The seed does
     not change the pairing property; it only decides the starting order of the
     teams, via a seeded shuffle (mulberry32), so different seeds give different
     but equally valid schedules. Input order is not trusted for fairness: the
     same inputs with the same seed always give the same output.

     No Date, no Math.random, explicit return types.
